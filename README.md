# Cashback Merge

Консольная игра в духе популярного 2048. Игрок сливает плитки с процентами кэшбэка, чтобы собрать максимальный приз.

**Главная особенность проекта** — встроенный движок симуляции (Monte Carlo). Бизнесу невыгодно, если джекпот получит слишком много людей. Проект позволяет прогнать десятки тысяч партий с виртуальными ботами и проверить, не разорится ли банк при текущих настройках акции, задолго до её запуска.

## Правила игры (Механика)
*   Поле `4x4`, по которому можно свайпать в 4 стороны (`UP, DOWN, LEFT, RIGHT`).
*   Две одинаковые плитки сливаются в одну удвоенного номинала (1% + 1% = 2%, 16% + 16% = 32%).
*   **Важное правило:** одна плитка не может сливаться дважды за один ход.
*   После каждого валидного хода появляется ровно одна новая плитка (вероятности выпадения задаются в конфиге).
*   Игра не заканчивается при сборе 32%, игрок доигрывает до лимита ходов.

## Бизнес-симуляция
В проект встроен движок симуляции, который:
1. Запускает тысячи партий с заданным `seed`.
2. Управляет игроками через паттерн «Стратегия» (реализован `RandomStrategy`).
3. Собирает статистику: распределение плиток, средний score, доля победителей.
4. Сверяет фактическую долю победителей с лимитом (`maxRewardAllowedRate`), который заложил банк.
5. Генерирует красивый Markdown-отчёт со статусом `OK` или `FAILED`.

## 🚀 Быстрый старт

Для запуска понадобится **JDK 25** или новее.

```bash
# 1. Запустить демо-режим (выведет стартовую доску)
./gradlew run

# 2. Запустить симуляцию (сгенерирует report.md)
./gradlew run --args="simulate --config config/campaign.example.json --players 10000 --strategy random --seed 42 --output report.md"

# 3. Запустить тесты и линтеры (как в CI)
./gradlew check
```

## MR1 — Модель, конфиг, начальное состояние

### Реализовано
- `Board` — поле 4x4, `Tile[][]` (пустые клетки — `null`).
- `Tile` — record с `int cashback`, валидация `> 0`.
- `GameStatus` — enum: `IN_PROCESS`, `FINISHED`.
- `GameSession` — состояние партии: board, movesLimit, movesUsed, status.
- `CampaignConfig` — конфиг с валидацией (boardSize > 0, movesLimit > 0, spawnRules не пусто, сумма вероятностей = 1 через `BigDecimal.compareTo`, maxRewardCashback в rewardTable).
- `ConfigReader` — чтение JSON через Jackson с DTO-вложенными классами. Вероятности — `BigDecimal`.
- `GameService.startGame(config, seed)` — создаёт поле и расставляет 2 стартовые плитки weighted random.
- `ConsoleUI.printBoard` — текстовый вывод поля.

### Запуск
- Игра: `./gradlew run`
- Тесты: `./gradlew check`

### Принятые решения
- **`BigDecimal` для вероятностей** — ТЗ запрещает `double`. Сумма вероятностей проверяется точно: `compareTo(BigDecimal.ONE) != 0`.
- **DTO внутри `ConfigReader`** — Jackson парсит JSON в `ConfigDto` с String-полями, потом конвертация в домен.
- **`LinkedHashMap`** для spawn-правил — сохраняет порядок вставки, чтобы seed был воспроизводим.

## MR2 — Движок ходов

### Реализовано
- `Motion` — enum: UP, DOWN, LEFT, RIGHT.
- `MoveResult` — record с `moved` и `scoreGained`, валидация инвариантов.
- `GameService.applyMove(session, motion)` — сдвиг и слияние по правилам тз.
- Обработка всех четырёх направлений через `extractLine`/`setLine`/`reversed`.
- Score начисляется только за слияния (значение результата).
- После валидного хода спавнится ровно одна новая плитка.
- `GameSession.addScore`, `recordMove`, `getScore`, `getRandom`.

### Принятые решения
- **Одна плитка не сливается дважды:** после слияния индекс `i += 2` — пропускаем оба «родителя», новая плитка не участвует в следующем сравнении.
- **Унификация направлений:** RIGHT/DOWN — реверс линии, обработка как LEFT/UP, реверс обратно. Один `processLine` на все направления.
- **`Random` в `GameSession`:** seed один на партию, включая spawn после ходов.
- **Валидность хода:** `processLine` возвращает `changed` — сравнивает линию до/после. Если ни одна линия не изменилась — ход невалиден.

## MR3 — Награды, симуляция, отчёт

### Реализовано
- `PlayerStrategy` — интерфейс для стратегий ботов.
- `RandomStrategy` — бот, выбирающий случайное направление.
- `SimulationReport` — record с результатами симуляции.
- `Simulator` — движок симуляции: запускает N партий, собирает статистику.
- `MarkdownReportWriter` — генератор отчёта в формате Markdown.
- `GameService.getReward()` — награда по максимальной плитке (если плитка >= `maxRewardCashback`, выдаётся максимальная награда).
- Команда `simulate` в CLI с аргументами `--config`, `--players`, `--strategy`, `--seed`, `--output`.
- Проверка бизнес-ограничения: `actualMaxRewardRate <= maxRewardAllowedRate -> OK, иначе FAILED`.

### Запуск симуляции
```bash
./gradlew run --args="simulate --config config/campaign.example.json --players 1000 --strategy random --seed 42 --output report.md" --console=plain
```
### Принятые решения
- Паттерн «Стратегия»: движок Simulator не знает, как именно бот выбирает ход. Он просто вызывает strategy.chooseMove(). Это позволяет легко добавить GreedyStrategy в будущем.
- Обработка невалидных ходов: в симуляции случайный бот может часто биться в стену. Если ход не меняет поле, Simulator пробует остальные три направления. Если все невалидны — игра прерывается.
